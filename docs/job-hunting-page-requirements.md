# Job Hunting Page Requirements

## Goal

ホームダッシュボードとは別に、就活専用の管理ページを追加する。
このページでは、就活で日常的に使うサイト、応募企業のアカウント情報、就活用 Gmail の確認導線を一箇所に集約する。

## Expected Value

- 就活に必要な情報へ最短でアクセスできる
- 企業ごとのログイン情報や応募状況を一覧で確認できる
- 就活用メールの見落としを減らせる

## Scope

初期スコープは以下の 3 つ。

1. 就活でよく使うサイトの一覧
2. インターン応募企業ごとの ID 管理
3. 就活用 Gmail の確認導線

## Functional Requirements

### 1. 就活サイト一覧

- よく使う就活サイトをカードまたはテーブルで一覧表示する
- 各サイトごとに以下を管理できる
  - サイト名
  - URL
  - 用途メモ
  - ログイン ID
  - パスワード管理方法
  - 備考
- サイト一覧からワンクリックで外部サイトを開ける
- 利用頻度が高いサイトを上部に固定できる

### 2. 応募企業アカウント一覧

- インターンを出した企業ごとに情報をリスト化する
- 企業ごとに以下を管理できる
  - 企業名
  - 応募職種または応募コース
  - 応募日
  - 選考ステータス
  - ログインページ URL
  - ログイン ID
  - パスワード管理方法
  - 締切や次回アクション日
  - メモ
- 企業一覧はステータス順や締切順で見られるようにする
- 選考中、結果待ち、完了などで絞り込みできるようにする

### 3. Gmail 確認

- 就活用 Gmail をすぐ確認できる導線を用意する
- 初期案は以下の 2 段階で考える
  - 最低限: Gmail を開くリンクを置く
  - 拡張: 未読件数や重要メールの有無を表示する
- 可能なら「新着あり」「未確認あり」などの状態がホームや就活ページ上で見えるようにする

## Security Requirements

パスワードをアプリ内に平文で保存するのは避ける。

- パスワードそのものは原則保存しない
- 代わりに以下のどれかで管理する
  - 1Password など外部パスワードマネージャの参照先
  - macOS キーチェーン等の安全な保管先
  - 「保存場所メモ」のみ保持
- アプリ側で保持する場合でも、最低限以下が必要
  - 暗号化
  - マスターキーの分離
  - 表示時のマスク
  - コピー時のみ一時表示

## UI Requirements

- ホームから就活ページへ遷移できる
- 就活ページの先頭に今日やることの簡易サマリーを置く
- 下記の 3 セクションを分けて表示する
  - 就活サイト
  - 応募企業
  - Gmail
- スマホでも一覧が崩れないこと
- ID はコピーしやすくする
- パスワードは表示しないか、明示操作時のみ表示する

## Initial MVP

最初の実装はここまでに絞る。

1. `/job-hunting` ページ追加
2. ホーム画面に就活ページへの導線追加
3. 就活サイト一覧を表示
4. 応募企業一覧を表示
5. Gmail を開くボタンを表示
6. パスワードは保存せず、`credential_hint` のみ管理

## Phase 2 Ideas

- Gmail API 連携で未読件数表示
- 選考ステータス更新フォーム
- 締切が近い企業の強調表示
- タスク機能との連携
- 企業ごとのメールスレッドや提出物リンク管理

## Open Questions

- パスワードは完全に保存しない前提でよいか
- Gmail はまずリンクだけでよいか、それとも未読件数まで必要か
- 応募企業は「インターンのみ」か、「本選考」も含めるか
- ステータスの初期定義をどうするか
- ホーム画面にも就活の未対応件数を出すか
