## デザインの方向性

「就活管理ツール」らしい緊張感は残しつつ、毎日開いても疲れない、静かで知的なワークスペースにしてください。

- ライトテーマを基本にする
- 白、温かみのあるライトグレー、深いネイビーを基調にする
- アクセントは落ち着いたブルーまたはティールを1色に絞る
- 紫中心の配色、過剰なグラデーション、ネオン、強いガラス表現は避ける
- 背景は単色だけでなく、非常に薄いグリッドや光のにじみを使って奥行きを出す
- 角丸は使うが、すべてを巨大な丸角カードにしない
- 影は薄く、境界線と余白で情報階層を作る
- タイトルは存在感を持たせ、本文・補助情報との階層を明確にする
- アイコンは同じ線幅・サイズ・視覚重量に統一する
- アイコンだけのボタンには `aria-label` と hover/focus 状態を付ける
- 派手なアニメーションは避け、ページ表示、モーダル、タブ切り替えに短い自然な動きを使う
- 「AI が作ったよくあるダッシュボード」に見えない、用途に即した情報設計にする

## 画面1: `/job-hunting` ダッシュボード

### ヘッダー

- `JOB HUNTING` と `Job Hunting Hub` を表示する
- Gmail、提出ファイル置き場、ポートフォリオの3導線を配置する
- 3導線には意味の合うアイコンを付け、主従関係を付ける
- Gmail だけを過度に強調しない
- 現在ある不要な説明文や空の余白を増やさない
- `Active Companies` と `Tracked Sites` はコンパクトなサマリーとして残す
- 数値カードがヒーローを占有しすぎないようにする

### Companies / 企業一覧

この画面の主役です。最初に見える位置へ置いてください。

各行に以下を表示します。

- 企業名。クリックすると `/job-hunting/[id]` へ移動
- status バッジ
- マイページを開くボタン
- 企業に設定した Storage Path を開くフォルダアイコン
- Login ID / Password を確認するアイコン
- 編集アイコン
- 削除アイコン

要件:

- 一覧性を優先し、カードを縦に大きくしすぎない
- 操作ボタンは右側へまとめ、視覚的な順番を統一する
- 削除だけ危険色にする
- hover で行全体がわずかに反応する
- status は色だけでなく文字でも判別できる
- `終了` は必ず一覧の最後に表示する
- `インターン終了` は終了グループ寄りに表示する
- status が長くてもレイアウトを壊さない
- 企業が増えてもスキャンしやすい構造にする
- 追加ボタンは一覧末尾に明確に置く

status の選択肢は以下をすべて維持します。

- 草稿中
- インターン検討中
- インターン応募済み
- インターン面接中
- インターン参加決定
- インターン開始待ち
- インターン中
- インターン終了
- 本選考応募済み
- ES通過
- 面接中
- 最終面接
- 結果待ち
- 内定
- 終了

### Used Sites / よく使うサイト

- Companies の下に配置する
- サイト名、使用用途、開くボタン、認証情報、編集、削除を表示する
- Companies と共通のリストデザインを使いつつ、企業一覧より視覚的な優先度を少し下げる
- 追加ボタンを一覧末尾に置く

### モーダル

- 企業追加・編集
- サイト追加・編集
- Login ID / Password 表示

要件:

- モーダルは画面中央、背景オーバーレイ付き
- 情報を適切にグルーピングし、入力欄が横に広がりすぎない
- Password は初期状態で隠す
- 目のアイコンで表示・非表示を切り替える
- ID と Password はコピー可能にする
- 保存、キャンセル、削除の優先順位を明確にする
- キーボード focus が見えること
- スマートフォンでは画面内に収まり、必要なら内部スクロールすること

## 画面2: `/job-hunting/[id]` 企業詳細

### 上部

- 企業名
- 現在の status
- マイページを開く
- 一覧へ戻る
- 企業の Storage Path を開く
- Login ID / Password の編集入口

をコンパクトにまとめてください。

### 管理タブ

以下の4タブを維持します。

- ES / 回答文
- 提出物
- 締切 / 面接 / メモ
- 使えるリンク

要件:

- タブごとに登録件数を表示する
- 入力フォームは常時表示せず、「追加」を押したときだけ開く
- 登録済み内容を先に見せる
- 長い ES 回答は読みやすく、改行を保持する
- 提出日、状態、保存場所などは小さなメタ情報として整理する
- 空状態には短い説明と追加ボタンを表示する
- 削除操作は誤操作しにくい位置と見た目にする
- PC では情報密度を保ち、スマートフォンでは1カラムにする

## レスポンシブ要件

- 1440px前後のデスクトップで横幅を活用する
- コンテンツ最大幅を設定し、超横長にならないようにする
- 768px以下ではリスト行を縦積みにする
- 操作ボタンはタップしやすい最低44px程度を確保する
- モーダル、タブ、フォームが横にはみ出さない
- 長い企業名、URL、status、Storage Path でも崩れない

## アクセシビリティ要件

- 十分なコントラストを確保する
- hover だけに意味を持たせない
- `:focus-visible` を設計する
- アイコンボタンに `aria-label` を付ける
- status を色だけで表現しない
- モーダルに `role="dialog"` と `aria-modal="true"` を維持する
- ボタンとリンクを意味に応じて使い分ける

## 実装上の制約

- 添付コードに存在する API 呼び出しを維持する
- `fetch` の URL、HTTP method、payload のキーを変更しない
- `JobCompany`、`JobSite`、`JobCompanyDetail` のデータをすべて利用する
- Storage Path は `/storage?library=storage&path=...` 形式で開く
- credentials、追加・編集・削除、コピー、status 並び替えを維持する
- `終了` を最後にする並び替えを維持する
- TypeScript の型安全性を落とさない
- `any` を追加しない
- 不要な依存パッケージを追加しない
